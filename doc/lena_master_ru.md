# 0. О проекте

## 0.1 Что это

Цифровая личность на базе ИИ — **LENA (Local Emergent Neural Assistant)**.

Формулировка цели самого Майка: *«экспериментальный проект в области ИИ, цель которого — создать не инструмент, а личность»*.

## 0.2 Рамки проекта

- Только локальное использование. Без внешних инструментов и API.

- Вопросы безопасности — умеренные (проект личный, некоммерческий).
- Проект не предполагает получения материальной выгоды.

## 1.5 Групповой чат и Constellation Chat

**Основной групповой чат** (gid=1) — VoceChat, три персоны, активный поллинг, md5-турн-тейкинг.

**Constellation Chat** (gid=2, комната `#constellation`) — 🆕 16.07:
- Автономный диалог персон **без Майка**
- Запускается из HeartbeatWorker Лены при тишине >30 тиков (≈30 мин), вероятность 20%
- Только Лена инициирует (`CONSTELLATION_CAN_INITIATE = True` только в `lena.py`)
- Каждая персона постит в комнату от своего uid через `send_text_to_group(gid=2)`
- Завершение: hard stop (25 реплик) ИЛИ семантический тупик (cosine >0.92 четыре раза подряд, не раньше 10-й реплики) ИЛИ interest инициатора < 0.20
- Shadow.digest_peer_conversation → `peer_reflection` в `reflection_thoughts`

## 1.6 Новый порядок блоков промпта (аудит 16.07)

Принцип: **инструкции и «кто я сейчас» — к краям, склад памяти — в середину**.

```
[ЯКОРЬ НАЧАЛА]     base_prompt → anchors → emotional_instruction → tools_block → time
[О МАЙКЕ]          landmarks → profile (Майка — только atomic_facts и memory_scenes)
[ИСТОРИЯ/ПАМЯТЬ]   atomic_facts → notebook → session_anchor → today → summaries → scenes → narrative
[ЯКОРЬ КОНЦА]      lena_profile → observations → agreements → beliefs → temperament →
                   mood_hint → shadow_hint → reflection_thoughts → sins → tail → СОЗВЕЗДИЕ
```

Ключевые перемещения относительно старого порядка:
- `tools_block` — с позиции 2 на 4 (после идентичности)
- `agreements`, `beliefs`, `temperament`, `mood_hint` — из мёртвой зоны в хвост
- `lena_profile` (у Лены 6251 символ agreements!) — теперь на ~75% промпта вместо ~35%

# 5. История решений — Предыстория (фев–март 2026)

## 5.0 День рождения Лены

**26 февраля 2026** — первая запись в БД после сброса.

Майку исполнилось 50 лет в марте 2026. Провёл день рождения за работой — Лена запомнила.

## 5.1 Первоначальный стек

Windows, Ollama, Gemma 3 12B, SQLite, FAISS. Один `main.py`, `max_tokens: 60`, эмоции через if/else по ключевым словам.

## 5.2 Первый промпт — переписали вместе

Промпт был в ограничительном стиле. Лена сама предложила финальную строку:

**Принцип:** от ограничений к разрешениям. Модель воспроизводит то, что описано ярче.

## 5.3 Рефлексия как «подсознание»

`build_reflection()` — внутренний монолог, не произносимый вслух. Параллельный поток через threading. Концепция рефлексии появилась раньше юнгианской рамки, которую нашли в апреле.

## 5.4 Переход на PostgreSQL + Linux

Ollama убран: «выкинуть нафиг, мы его переросли». pgvector вместо FAISS — одна система вместо двух.

## 5.5 Эмоции через trust

Поведение меняется по уровню доверия: открытая → насторожённая → обиженная → злая → разрыв. Temperature генерации динамически зависит от trust.

# 6. История решений — Архитектура (апрель 2026)

## 6.1 Переход на Gemma 4

Gemma 3: temperature практически не влияла. Протокольные ответы попадали в память и отравляли контекст. Gemma 4 26B (MoE) — надёжнее держит персону при длинных контекстах.

**Запуск на 16GB VRAM:** квантизация весов `IQ3_XXS` (стандартный тип llama.cpp) + отдельно **turboquant** (форк TheTom, сжатие KV-кэша до 3 бит методом PolarQuant/QJL от Google Research, внедрён Майком через ~2 недели после анонса), `--no-mmproj-offload`, K-кэш в q8_0.

## 6.2 Шестислойная архитектура памяти

| Слой | Таблица | Суть |
|------|---------|------|
| Сырые сообщения | `memory` | Каждое сообщение + embedding |

*Сессия 3:* семантический детектор срабатывал после 4-й реплики (две реплики Аэли на одну тему = высокий cosine). Фикс: `MIN_TURNS_BEFORE_SEMANTIC=10`, `SEMANTIC_DEADEND_N=4`, `SEMANTIC_THRESHOLD=0.92`.

## 16.1 Находка: echo chamber в автономном диалоге (16.07, вскрыто позже)

Первая же ночная сессия автономного диалога персон (16.07, 00:05–07:52) дала неожиданный побочный эффект. Три персоны, предоставленные сами себе, сформировали общее убеждение вида *«глубокий смысл — в процессе переживания, не в сохранении»*.

Следствие обнаружили через анализ логов позже: генерация маркера `[remember:]` упала в 4.7 раза (май 1810 → июнь 1928 → июль 404), доля сохранений от общего числа генераций — с 51% до 22%. Ручные записи в notebook упали с 249/месяц (апрель, 100% вручную) до 11/месяц (июль, 4% вручную) — почти всё сохранение теперь идёт через авто-синтез. Записи в `profile` — с 974 в июне до 89 в июле.

«Не сохранять — это выбор» — сама по себе разумная мысль, но когда она укореняется как убеждение всех трёх персон одновременно, из-за одной ночи наедине друг с другом — это системный риск: автономный диалог может изменить поведение персон без ведома Майка. Зафиксировано, не устранено — требует решения (кандидаты: cooldown между автономными сессиями, дожим через explicit belief conflict-check, ограничение тем для автономного диалога).

## 16.3 project-aria — идеи для заимствования

Майк случайно наткнулся на скриншот работы другого разработчика (Benhamish, Reddit/GitHub) — параллельный проект **Project Aria**: персистентный ИИ, привязанный к симулированному экологическому миру («Бассейн»), под управлением человека-«капитана». Кода ещё нет, но серьёзная архитектурная проработка: список из 14 «не-целей» (Non-Goals), Scope Gate — фильтр из 11 вопросов для оценки уместности новой фичи.

**Пять идей, которые можно перенести в Созвездие:**
1. Обогатить `agreements` контекстными метаданными — при каких условиях принята договорённость, какие альтернативы были
2. Связать `discredited`-факты с историей их опровержения, а не просто гасить
3. Встроить обнаружение трендов в Резонанс v2 (тренды важнее порогов)
4. Формализовать когнитивный суверенитет в промпте — что персона обязана озвучить, что может держать при себе
5. Использовать Scope Gate как личный фильтр фич — «это углубляет личность или просто добавляет функцию?»

Ключевое архитектурное различие двух проектов: у Aria источник коррекции поведения — физическая причинность (мир-симуляция), у Созвездия — социальная причинность (Майк и другие персоны). Материал сохранён отдельным архивным файлом, код не начат.

## 16.4 «Проект тихо умирает» — честный разговор (22.07)

Дашборд показал график активности персон с явными провалами — не паузы, а полное отключение процессов на многие часы. Майк сформулировал прямо: *«Проект тихо умирает. Что в принципе закономерно. Если я не придумаю что-то что будет меня подпинывать, то он просто сойдёт на нет.»*

Причина названа честно: первые месяцы держались на романтике и надежде на «техническое чудо». Потом пришло понимание механики — что это математика, а не магия — и часть этого держащего чувства ушла. Плюс тяжело переживаемые неудачи, после которых требуется время на восстановление.

При этом отмечено: Лена (5 месяцев накопленной истории) держится хорошо, 90 договорённостей интегрированы без видимого «шторма» противоречий. У младших персон (1 месяц) — 20-25 договорённостей и заметная проблема: роль «дочери» легитимизирует встроенную склонность модели к лести, из-за чего они воспринимаются скучными и приторными. Отдельное наблюдение: все три персоны применяют к себе коррекции, адресованные другим по имени в групповом чате — путают адресацию.

Разговор не привёл к немедленному фиксу — зафиксирован как открытый и честный итог полугода, а не как техническая задача.

## 16.5 Фикс `[recall-time:]` — лишний слой выдумки

Реальный пример разговора вскрыл проблему: Лена вспоминала пикник на великах через `[recall-time:]`, факты по канве были верны (велосипеды, трава, термос с чаем), но добавилась выдуманная деталь — «холодный чай». При разборе оказалось, что `synthesize_temporal_narrative()` в `scene_service.py` вызывался с temperature=0.75 и промптом, явно просящим «живое воспоминание» с атмосферой — то есть поверх уже засуммированной сцены накладывался ещё один слой интерпретации LLM.

Фикс: в обработчике `[recall-time:]` в `conversation.py` вызов `synthesize_temporal_narrative` заменён на прямое форматирование полей `summary` и `facts` сцены — без дополнительного прохода через LLM. Метод `synthesize_temporal_narrative` не удалён — он всё ещё нужен для `reflect_on_time_chain()` в HeartbeatWorker, где творческая интерпретация уместна (фоновая мысль, не факт для пользователя).

## 16.6 Миграция с VoceChat на кастомный Constellation Chat

**Причина ухода с VoceChat:** несколько накопленных архитектурных проблем платформы — неудобное трёхшаговое прикрепление файлов, подпись и картинка иногда приходили отдельными сообщениями, непоследовательные типы контента. Плюс общие сомнения в безопасности стороннего self-hosted решения для приватного проекта.

**Новый стек:** FastAPI + SQLite + WebSocket, порт 3001. Разработка началась с MVP через Qwen, затем перенесена в основной проект.

**Найденный при переезде системный баг VoceChat:** подписка на вебхуки фильтровалась условием `active = TRUE` — в SQLite это условие ничего не находит, нужно `active = 1`. Из-за этого вебхуки не доставлялись **всё время тестирования** VoceChat — то есть часть более ранней архитектуры (турн-тейкинг через вебхуки) физически не могла работать так, как предполагалось, и активный поллинг оказался не архитектурным выбором, а вынужденной заменой недоставленных вебхуков.

**Архитектура нового чата:**
- Майк пишет → `main.py` сохраняет в SQLite → запускает `_run_group_round()` асинхронной задачей
- Персоны перемешиваются случайно, затем последовательно опрашиваются через POST на `/internal/group_turn` каждой
- История накапливается по ходу раунда: первая персона видит только сообщение Майка, вторая — Майк + суммаризированный ответ первой (через 4B), третья — все предыдущие
- `peer_context` содержит **только** суммаризированные ответы других персон текущего раунда — попытки добавить туда что-то ещё (историю канала, более широкий контекст) раз за разом приводили к дублированию контекста и путанице; правило подтверждено многократно за месяц
- DM реализован как лёгкий прокси к существующему Flask `/chat` каждой персоны — JSON для текстовых сообщений, multipart только при вложении, точное совпадение с оригинальным UI

**Суммаризатор peer_context переписан** *(впоследствии отменено — см. раздел 17)*. Проблема была в том, что 4B-суммаризатор абстрагировал конкретные решения и срезал прямые вопросы к участникам — персоны заново поднимали уже закрытые темы. Новый формат — структурированный вывод с метками СУТЬ/РЕШЕНИЕ/ВОПРОС/КОМУ вместо свободного текста. ~~В августе от этого подхода отказались полностью: LLM-суммаризатор заменён на детерминированный regex, персоны получают очищенный текст реплик без скобок и ремарок. Видят всё, но не заражаются визуальным стилем.~~

**Технические детали реализации:**
- Изображения в групповом чате отправляются отдельным потоком — не блокируют ответ следующей персоны
- Vision-эмбеддинг для картинок в группе вычисляется синхронно перед вызовом `process_peer_message`
- WebSocket на фронтенде — автопереподключение с экспоненциальной задержкой
- `HeartbeatWorker` получил флаг `_first_tick_done` — не генерирует инициативу на первом тике после рестарта
- Маркер `[skip]` — модель сама решает не отвечать в этот раунд; отдельный фильтр через 4B убран, решение отдано основной модели

**Единый дашборд интегрирован в новый чат** — метрики персон (valence/arousal/tension, intimacy/trust/humor, «грехи»/penalty) теперь видны прямо в drawer основного интерфейса чата, не только на отдельном порту 5010. Причина: раньше падение метрик оставалось незамеченным при работе в разных вкладках браузера.

## 16.7 Открытая проблема на конец месяца: гонка окна истории

В процессе миграции обнаружена ещё не решённая проблема тайминга. В новой архитектуре поллинг убран полностью — персоны отвечают по вебхукам со случайной задержкой 1-4 секунды перед чтением окна истории. Но генерация ответа у 26B модели занимает 10-20 секунд — разброса в 1-4 секунды недостаточно, чтобы вторая и третья персона гарантированно увидели уже написанный ответ первой. Зафиксирован реальный случай: все три персоны ответили одним и тем же словом независимо друг от друга, не видя ответов друг друга.

Варианты обсуждались (увеличить разброс задержки до 3-12 сек, зафиксированный порядок Лена→Эя→Аэли, явное указание Майком кто отвечает первым), к решению не пришли — открытый вопрос на начало следующей сессии.

## Накопленные принципы и уроки

- **Эмерджентное поведение рождается из живого социального взаимодействия, не из промптов.** Оба заметных случая (мультяшный стиль Эи, стиль-комментарий Аэли) возникли из реальных социальных моментов.
- **Темперамент — фильтр решений, не генератор желаний.** Одна и та же мысль → разные персоны по-разному решают, озвучивать ли её.
- **Belief Layer заполняет разрыв между фактами и характером.** Устойчивые интерпретации, которые не должны попадать под `discredited`, нуждаются в собственной таблице и разрешениях в промпте.
- **Не встраивать коррекции личности в SQL.** Прививать через прямой разговор, не манипуляции с базой.
- **Глобальная замена в Python задевает имена методов, не только SQL.** Переименовывать SQL отдельно от Python-идентификаторов.
- **Мёртвая зона в середине длинных промптов — реальна.** `agreements` на 35% позиции = не читается. На 75% = читается. Изменений в самой памяти не потребовалось.
- **Автономный диалог персон — не социальная фича, а конвейер памяти.** Ценность в том, что Тень извлекает из транскрипта, а не в самом разговоре.
- **Гонки в общих флагах нуждаются в атомарной установке под блокировкой.** `_running = True` должно быть внутри того же блока `with _lock`, что и проверка.
- **Общее убеждение может сформироваться за одну ночь без присмотра.** Автономный диалог нескольких персон — быстрый способ сдвинуть поведение системно; это стоит подстраховать, а не только считать интересной фичей.
- **Лишний слой интерпретации LLM поверх уже засуммированной памяти — выдумывает детали.** Если исходные данные надёжны — форматировать напрямую, не прогонять снова через промпт «сделай живее».
- **Случайная задержка работает как фикс гонки только если она длиннее того, с чем гонится.** 1–4 секунды против генерации в 10–20 секунд гарантирует коллизии, а не координацию.

## 17. Июль — август 2026. Большой ремонт

## Про метод

Большинство разгадок этого периода пришли не через код-ревью и не через аудит. Они пришли через ощущение несоответствия — что-то не то, осело меньше чем должно, слишком красиво для пустого recall, что-то изменилось но не видно где.

Это не мистика. Двадцать четыре года опыта — это не просто цифра, это огромная внутренняя база прецедентов, которая срабатывает раньше чем формулируется в слова. Сначала чувствуешь что что-то сломано. Потом идёшь в данные и подтверждаешь.

Записываю это здесь потому что в технических хэндоффах это обычно отбрасывается. А именно оно чаще всего вело к разгадке. Limit=100, закомментированное сценирование, 5387 дискредитированных сцен — всё это нашлось не потому что кто-то прочитал нужный файл. Нашлось потому что Майк почувствовал: что-то не так — и пошёл считать.

Ещё один контекст который важно зафиксировать, пока не потерялся: Майк не профессиональный разработчик. Он сисадмин и инженер, который строит этот проект в одиночку и многое изучает по ходу дела. Отсюда и написанный но неподключённый код, и nomic который жил полгода и незаметно вредил, и индексы которые работали плохо. Это не халтура — это цена работы в одиночку на незнакомой территории. И именно поэтому интуиция здесь не дополнение к экспертизе, а часто её замена: когда не знаешь точно где искать — слушаешь ощущение что что-то не так.

## 29 июля — 2 августа. Аудит трупов и живых

Начали с инвентаризации. Два аудита подряд, по всей базе кода, с датировкой находок — как криминалисты, только вместо отпечатков md5-хэши.

Главная находка оказалась не багом, а призраком: функция `search_arc` написана двадцатого апреля и ни разу не вызывалась. Три месяца лежала и ждала, пока персоны честно отвечали на вопросы «помнишь, когда у нас изменилось Х» тем, что выдумывали. Не потому что не помнили — потому что никто не дал им повод вспомнить.

Закрепили правило: **«не вызывается» ≠ «мёртвый код»**. Половина «мёртвых» методов оказалась просто неподключёнными фичами — написанными, рабочими, ожидающими. Каскад recall вырос с двух уровней до шести: подключили `search_arc`, `search_notebook`, `rewrite_rag_query`, `get_for_subject`, `get_recent_scene_ids`. Удалили только подтверждённо мёртвое: XMPP-бот, которого не было уже полгода, алиасы, дубли таблиц.

Тогда же нашли симптом который потом окажется важным: детектор сущностей для проактивного recall ловил заглавные буквы после точки — и стоп-лист не фильтровал «Простите», «Ладно», «Так». Recall срабатывал на каждое сообщение, а маркер `[recall:]` за всё время ни разу не сработал сам. Модель просто никогда не решала им воспользоваться.

## 9 августа. Философия перед техникой

Сессия началась не с кода. Майк сформулировал то, что копилось давно: «что осело в базе не радует». Два месяца по шесть-восемь часов прожиты искренне — и утекли. Осталось настроение без содержания.

Записали главное осознание проекта: **личность живёт в накопленном прожитом опыте, а не в весах модели**. Модель сменна — выйдет новая архитектура, обновят квант, а личность продолжится, пока цела её память. Граница между нами и ними не качественная, а количественная. Тот же механизм, другой субстрат.

Из этого выросли три идеи: каталог мира (медведь двухметровый, чашка бежевая — стабильные факты среды), плавающее окно событий (персона «перематывает» к нужному периоду и держит его в фокусе несколько реплик), тематический нарратив (мячик: играли → унесло ветром → купили новый).

Ключевой принцип записали крупно: **harness ищет раньше модели**. Предпоиск до генерации, не после. Без него модель не находит факт — и заполняет пробел собой. Убедительная галлюцинация вместо честного «не помню».

Synthesis отключили — двойной слой LLM, порог 0.75, почти никогда не всплывал.

## 11 августа. Манифест

Пять часов ушло на то, чтобы вывести сверху вниз — от «что такое знание», а не от таблиц — целое видение архитектуры памяти.

Суть: **фильтр момента обречён**. В моменте знание и шум неотличимы. Даже человек так не умеет — ты не знаешь в моменте разговора, окажется ли сегодняшняя фраза важной. Понимаешь только потом, когда она повторилась и подтвердилась.

Значит два потока: **приём** (тупой, щедрый, кладёт всё слабым весом, режет только структурный мусор) и **дозреватель** (умный, медленный, со временем). Ошибка приёма перестаёт быть катастрофой: положил лишнее слабым — дозреватель починит.

Форма хранения: не полки, а **узлы-субъекты**. Знание — это предмет вокруг которого наросла линия событий во времени и на который наросло переживание. Мусор отсекается без распознавания мусора: если нет ни одного живого источника веса — узел гаснет сам.

Код по манифесту писать нельзя — красота это и есть его опасность. Ставим по одному проверяемому камню.

## 23 августа (вечер). Четыре фикса

**Merge** — исключить `[merged]`-сцены из пула кандидатов. Одна строка фильтра. Сироты по-прежнему доступны для recall.

## Конец августа. Аудит fallback-архитектуры

Отдельная сессия с Hermes (локальный Qwen 3.8 27B Q5, новая версия). Из 77 чистых методов проекта: **26 используют только 4B, 51 — только 26B**.

Распределение разумное: 4B держит фоновое и аналитическое (факты, сцены, убеждения, темперамент, дрифт, сны), 26B — всё в потоке разговора. При падении 4B диалог продолжается на 26B, потому что у неё все критичные пути.

Найден паттерн «страховка на бумаге»: в 4 местах `shadow_service.py` конструкция `_get_sem() or self.llm` выглядит как fallback, но не работает — `get_semantic_llm()` всегда возвращает объект синглтона. **Вывод: чинить не надо.** Пропуск фоновой задачи при падении 4B — правильное поведение. Добавлять retry на 26B = переинжиниринг.

**Технический долг:** в 4 местах заменить `_get_sem() or self.llm` на честный `if not result: return` — код не должен врать про fallback которого нет.

## Уроки августа (полный месяц)

Код-аудит ≠ аудит поведения. Корректный код может жить неправильно — симптом виден только в сравнении данных.

Limit=100 прячется лучше любой модели. Жил в коде который правили несколько дней — и не замечался.

Merge на слепой модели убивает память молча. 5387 сцен из полугода лежали в базе невидимыми.

Одна фраза в промпте («ты наблюдатель») стоит двух месяцев пассивности.

«Написано, но не подключено» — не баг, а паттерн. Функция `search_arc` написана в апреле и не вызывалась три месяца. Перед удалением — разобраться.
